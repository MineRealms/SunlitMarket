# 完整经济系统 / 期货 / K 线 —— 可行性分析与设计

> 范围：在 SunlitMarket 现有「固定价货架 + 当铺柜台」之上，增加动态价格、价格指数、期货合约和 K 线面板。
> 本文只做设计分析，不含实现。任何一项落地前都应先跑通上一层的实测。

## 0. 结论先说

| 能力 | 可行性 | 主要障碍 | 建议 |
|---|---|---|---|
| 动态现货价（NPC 做市） | 高 | 只是公式和存档，无技术风险 | 先做 |
| 价格指数 + 日 K | 高 | 无，纯服务端计算 + 客户端画图 | 先做 |
| 玩家挂单（订单簿） | 中 | 人少时流动性枯竭、自成交、旁路套利 | 后做，先只对 NPC 做市商下单 |
| 期货（现金交割） | 中 | 保证金/强平/结算价操纵，逻辑复杂但不是不可能 | 分阶段 |
| 实物交割期货 | 低 | 物品搬运、区块加载、仓库爆炸、复制漏洞 | 不做 |
| 完整订单簿撮合（价格优先时间优先） | 低 | 5–20 人在线撑不起真实盘口 | 不做 |
| 杠杆借贷 / 做空裸卖 | 极低 | 无限印钱风险，一旦有洞就是经济崩盘 | 不做 |

关键判断：**这套东西能做，但价值不在「像交易所」，而在「让 Shipping Bin 的静态物价变成会波动的市场价格」。** 玩家数量少的时候，真实盘口是假的，做市商才是真的。

## 1. 现在的地基是什么

已有可复用的部分：

- 价格锚：整合包 global.trades（Shipping Bin 出货价），已经覆盖 529 个 FTBQ 条目。
- 交易入口：MarketService.handleAction 是唯一的成交路径，买卖都从这里走。
- 存档：SavedData 模式已成熟（StockData / LimitData / AlignmentData / ReputationData / UnlockData）。
- 每日钩子：SunlitMarketMod.onServerTick 已经按 getDayTime()/24000 做每日衰减，可直接挂 K 线收盘。
- 客户端：MarketScreen / CounterScreen 是自绘 Screen，没有第三方图表库依赖。
- 货币：Currency 以 numismatics 铜币 spur 为 1，全部价格是整数币值。

缺的部分：

- 价格不是状态，是规则里的常量；同一件物品今天和明天一个价。
- 没有成交历史，所以画不出任何曲线。
- 没有仓位概念，只有钱包余额。

## 2. 现货：从固定价到做市商定价

### 2.1 为什么不用订单簿当第一版

真实订单簿要求买卖双方同时在线且愿意挂单。假设服务器常年 5–15 人：

- 冷门物品永远没有对手盘，玩家挂单永远不成交；
- 热门物品被一两个大户吃干，价格瞬间跳 10 倍；
- 需要处理自成交、撤单风暴、部分成交、价格优先队列，代码量是现在的 3–5 倍；
- 一旦有人用两个账号对倒，K 线就是假的。

所以第一版应该是 **NPC 做市商 + 库存偏斜定价**：永远有对手盘，价格随库存移动。

### 2.2 库存偏斜定价（推荐第一版）

每件可交易物品维护一个做市库存 S 和目标库存 S0（默认 64 或按品类），中间价：

```
mid = base * clamp( (S0 / max(S,1)) ^ e , 0.25, 4.0 )
```

- e 是弹性系数，0.15–0.35。e 越大，库存变化对价格影响越剧烈。
- base 取 Shipping Bin 值（已有锚），所以价格天然和整合包经济一致。
- 买入（玩家买走）→ S 减少 → 价格上升；卖出 → S 增加 → 价格下降。
- 这是 Recettear / Mount&Blade 的做法，好处是：可预测、无操纵空间、离线也稳定、存档只要一个整数。

买卖价差：

```
ask = mid * (1 + spread/2)      // 玩家买入价
bid = mid * (1 - spread/2)      // 玩家卖出价
```

spread 按品类 4%–12%，赃物更高（风险溢价）。这个价差就是系统的「手续费」，天然回收货币。

### 2.3 加入成交冲击（第二版）

只靠库存，价格对单笔大单反应太慢，且可以被「分批小额」绕过。加一层瞬时冲击：

```
impact = 1 + k * sign(q) * sqrt(|q| / S0)     // q 为本次成交数量，买入为正
exec  = mid * impact
```

sqrt 让大单有惩罚但不是线性爆炸。k 取 0.02–0.05。

### 2.4 均值回归 / 回归基准

每个游戏日收盘做一次：

```
S += clamp(round((S0 - S) * 0.10), -4, +4)      // 库存缓慢回目标
mid = lerp(mid, base * drift, 0.05)             // 价格缓慢回锚
```

drift 是全局景气系数（0.9–1.1），可由服务器事件/季节调整，也可以由玩家总成交量推。不加这一步，长期会把库存吃空、价格钉在 clamp 边界。

### 2.5 数据与开销

- 状态：每个 (merchantId, itemId) 一个 int stock + 一个 int mid。按 600 个货池算，约 2.4 KB，忽略不计。
- 计算：只在成交时算一次，O(1)。不需要每 tick 遍历。
- 存档：并入新的 SavedData MarketData，10 秒或关服时落盘。

## 3. 价格指数：K 线的地基

### 3.1 为什么必须有指数

单个物品的成交量太低（一天可能 0 笔），直接画它的 K 线就是一条水平线加几个跳变，没有信息量。指数把同类物品聚合，才有连续价格。

建议 8 个指数：

| 指数 | 成分 |
|---|---|
| GRAIN 谷物 | 小麦、土豆、胡萝卜、甜菜、面包原料 |
| VEG 蔬果 | 番茄、卷心菜、莓类、瓜类 |
| FISH 渔获 | global.fish 全部 |
| ANIMAL 畜产 | 奶、蛋、肉、皮革、羊毛 |
| ORE 矿石 | 铁/铜/金/锌/铅/银原矿与锭、煤 |
| MAGIC 魔法材料 | AS/TC/BOT 的 19 个材料条目 |
| CRAFT 加工品 | 油、奶酪、枫糖浆、布料、料理 |
| ME 中州货物 | 夏尔/刚铎/洛汗/萝林/孤山的商品 |

赃物不进指数：来源不稳定、带 wanted、容易被刷，做成指数就是给洗钱开通道。

### 3.2 指数公式

加权几何平均，权重 w 取 30 日成交额占比（无成交时退回数量权重）：

```
index = exp( Σ w_i * ln(mid_i / base_i) ) * 1000
```

用几何平均而不是算术平均：单个物品暴涨不会把指数拉爆，且价格翻倍/减半对称。除以 base 是归一化，让指数从 1000 起步。

### 3.3 K 线采样

一个游戏日 = 24000 tick = 20 分钟现实时间。采样粒度可选：

| 周期 | tick | 现实 | 用途 |
|---|---:|---|---|
| 1D | 24000 | 20 分钟 | 主图，默认 |
| 4H | 4000 | 3.3 分钟 | 短周期，看日内 |
| 1W | 168000 | 2.3 小时 | 长周期，看趋势 |

每根蜡烛存：open / high / low / close / volume（以指数点计的成交额）。

聚合方式：不是收盘才算，而是每 100 tick 采样一次 index，更新当前蜡烛的 high/low/close；跨天时封蜡烛、开新蜡烛。这样即使中途重启，最多丢 100 tick 的极值。

### 3.4 存储与同步

- 环状缓冲，每个指数 240 根 1D + 240 根 4H。8 指数 × 480 根 × 5 个 int ≈ 77 KB，全在内存 + 一个 NBT long[] 数组，可接受。
- 同步：只同步客户端正在看的那个指数、那个周期，最多 120 根。每根 5 个 short（价格压缩到指数点，0–65535 够用）= 120 × 10 字节 = 1.2 KB，一个包搞定，远低于 32 KB 安全线。
- 客户端缓存 + 增量更新：新蜡烛封盘时只推最后一根。

## 4. 期货：能做，但要极其克制

### 4.1 形态选择

| 形态 | 结算 | 评价 |
|---|---|---|
| 现金交割指数期货 | 到期按指数收盘价现金结算 | **推荐**。无物品搬运、无仓库、无复制面 |
| 实物交割 | 到期交物品 | 放弃。物品上链=区块加载+漏斗+掉落物，等于给复制漏洞开门 |
| 永续合约 | 靠资金费率锚定 | 次选。资金费率要每 8 小时结算，玩家容易误解 |
| 期权 | 权利金 + 行权 | 后续再说，定价和 UI 都更复杂 |

第一版只做 **指数期货，现金交割，固定到期日**。

### 4.2 合约规格

```
标的      : 某个指数（如 ORE）
合约乘数  : 每 1 点 = 1 单位基础货币（spur 计价）
最小跳动  : 1 点
到期      : 开仓后第 7 个游戏日收盘（也可做 30 日）
交割      : 到期日收盘指数（TWAP）现金结算
保证金    : 开仓名义价值的 25%
维持保证金: 15%，低于则强平
手续费    : 开仓 0.2%，平仓 0.2%，交割 0.1%
```

例：ORE 指数 1000，买 1 手 = 名义 1000 币，占用保证金 250 币。指数涨到 1100，浮盈 100 币（40% 保证金收益率）。跌到 750 触发强平，本金接近归零。

### 4.3 结算价必须抗操纵

如果按「到期那一秒的指数」结算，大户可以在最后 10 秒砸盘/拉盘。用 **到期前 N 个采样点的 TWAP**：

```
settle = mean(index[t-10], index[t-9], ..., index[t])   // 10 个 100-tick 采样
```

并且到期前最后一小时禁止开新仓（只能平仓）。这两条能把操纵成本抬高一个量级。

### 4.4 保证金与强平

每 100 tick 对每个持仓重算：

```
equity = 保证金余额 + 未实现盈亏
维持线 = 名义价值 * 15%
if equity < 维持线: 强平（市价平仓，剩余退给玩家）
```

强平必须有滑点惩罚（按冲击公式成交），否则「爆仓无损」会变成免费杠杆。

### 4.5 仓位上限（防逼仓）

单玩家/单 FTB 队伍对单一合约的持仓上限：

```
maxLots = max(1, floor(指数池深度 / (合约乘数 * 指数值 * 20)))
```

指数池深度取近 7 日该指数成分的总成交额。粗略地说：让任何人最多持有市场 5% 的敞口。小服务器就直接写死 20 手。

### 4.6 期货价格从哪来

两个选择：

1. **自己撮合**（玩家之间成交）：需要盘口，人少时无成交，弃。
2. **NPC 做市商报价**：

```
fair = index * (1 + basisRate * daysToExpiry)
quote = fair * (1 ± spread/2)
```

basisRate 可以取 0（无风险利率近似为 0），也可以给 0.2%/日 的持有成本。到期日 daysToExpiry=0，自然收敛到指数，不需要强制收敛逻辑。

做市商的库存风险用「报价偏斜」对冲：玩家集体做多，做市商空头增加，就把报价往下压一点，形成天然的挤兑成本。

### 4.7 与现有系统的冲突点

- **货币来源**：期货是零和的（不含手续费），但保证金放在钱包里冻结而不是销毁。需要冻结字段，不能直接扣 Currency.balance。
- **对齐/通缉**：期货不涉及物品，不应产生 wanted；但可以给「爆仓」一个士气/声望小惩罚，属于可选。
- **FTB 队伍**：仓位挂 player 还是 team？建议跟 wantedScope 一样做成配置项，默认 personal。
- **关服/重启**：持仓、保证金、冻结额必须进 SavedData，且结算要在 onServerStarted 时补算（服务器停机跨过了到期日）。

## 5. K 线面板：怎么画

### 5.1 技术路线

MC 1.20.1 的 Screen 里用 GuiGraphics.fill(x1,y1,x2,y2,argb) 画矩形就够了：

- 蜡烛实体 = 一个 fill 矩形；
- 上下影线 = 两个 1px 宽 fill；
- 成交量 = 底部小矩形；
- 均线 = 用 fill 画折线（每段 Bresenham 式小矩形，或直接用 RenderSystem 的 line，但在 GUI 里 fill 更稳）。

60 根蜡烛 × 约 5 个矩形 = 300 次 fill，任何客户端都能承受。不需要引入图表库。

### 5.2 面板布局

```
+--------------------------------------------------+
| [GRAIN] [VEG] [FISH] [ORE] [MAGIC] [CRAFT] [ME]  |  <- 指数切换
|  1D  4H  1W                        O 1012 C 1040 |
|                                                  |
|        ┃                                        |
|     ┃  ┃   ┃                                    |
|   ┃ ┃  ┃ ┃ ┃  ┃                                  |
|                                                  |
|  ▁▂▃▅▂▁▃▅▇▅▃▂▁▂▃▅  成交量                        |
|                                                  |
| MA5 1021  MA20 998   最高 1102  最低 941          |
+--------------------------------------------------+
```

### 5.3 交互

- 左侧切指数，顶部切周期；
- 鼠标悬停显示该蜡烛的 O/H/L/C/量；
- 键盘左右移动选中蜡烛（可选）；
- 不做缩放、不做指标编辑，控制复杂度。

### 5.4 数据获取流程

```
玩家打开面板 -> C2S 请求(index, period)
服务端 -> S2C 返回该指数该周期最近 120 根蜡烛
新蜡烛封盘 -> S2C 增量推送最后一根（只发给打开着该面板的人）
```

包体：120 根 × (open,high,low,close,volume) × short = 1.2 KB。

## 6. 数值与经济平衡

### 6.1 货币回收（最重要的部分）

动态市场会让货币总量失控，必须有 sink：

| sink | 强度 |
|---|---|
| 买卖价差（spread） | 每笔 4–12%，主回收 |
| 期货手续费 | 每笔 0.2–0.5% |
| 强平滑点 | 一次性，大额 |
| 通缉罚金 | 已有 |

如果服务器通胀明显（物价指数长期单调上升），就把 spread 和手续费调高，而不是加新税。

### 6.2 与 Shipping Bin 的关系

Shipping Bin 是「无限量、固定价」的对手盘，这是最大的套利入口：

- 如果 NPC 做市商卖出价 < Shipping Bin 价，玩家可以无限买了丢箱子；
- 所以规则：**任何可交易物品的 ask 必须 ≥ shippingValue**。
- 反过来，bid 永远 < shippingValue，玩家不会从做市商买了直接出货。

这一条是硬约束，应该写成启动断言，静态检查脚本也要覆盖（类似现在的 0 个 ask>=market 的检查，反过来再加一条 ask>=shipping）。

### 6.3 与 GT / 后期产线的关系

- 期货不产生物品，不会破坏 GT 的产量平衡；
- 但会让「囤货等涨价」变得有意义：GT 玩家可以先囤板/电路，等指数涨再卖。这是我们要的；
- 唯一要防的是「无限产量 → 无限砸盘 → 指数归零」：给每个指数的做市商一个最低价（base*0.4），跌到底就当无限收货，避免经济自杀。

## 7. 分阶段实施建议

| 阶段 | 内容 | 风险 | 依赖 |
|---|---|---|---|
| E1 | MarketData（stock/mid）+ 库存偏斜定价，替换固定 buy/sell | 低 | 现有货架 |
| E2 | 指数计算 + 日/4H 蜡烛 + 持久化 | 低 | E1 |
| E3 | K 线面板（只读） | 低 | E2 |
| E4 | 期货合约：开仓/平仓/保证金/到期现金结算 | 中 | E2 |
| E5 | 强平 + 仓位上限 + TWAP 结算 | 中高 | E4 |
| E6 | 玩家挂单（对做市商挂限价单） | 高 | E1 |
| E7 | 指数掉期/期权 | 极高 | E4–E5 |

建议先做 E1–E3，把「会波动的物价 + 能看的图」跑起来；E4 之前必须先有至少一周的指数历史，否则期货没有可信标的。

纯函数部分（IndexMath、PriceEngine 的定价函数）必须写单测，这是唯一能在没有服务器的情况下验证的核心。

## 9. 明确不做

- 实物交割、仓库、仓单；
- 裸卖空、借贷、利息；
- 玩家之间的撮合引擎（第一版以内）；
- 跨服、跨存档的行情；
- 用真实世界时间驱动行情（必须用游戏日，否则离线就变盘）。

## 10. 风险清单

1. **人少 → 行情假**：所有价格都是做市商报价，K 线反映的是我们的公式而不是玩家博弈。要在面板上标注「做市商报价指数」。
2. **大户操纵**：仓位上限 + TWAP 结算 + 冲击成本，三件套缺一不可。
3. **存档膨胀**：只存环状缓冲，绝不存每一笔成交明细。成交明细只保留最近 200 笔用于审计。
4. **重启丢蜡烛**：跨天封盘要在 onServerStarted 检查 lastCloseDay，补一根空蜡烛避免断图。
5. **与 Shipping Bin 套利**：ask >= shippingValue 是硬约束，必须断言 + 静态检查。
6. **货币超发**：spread 和手续费是唯一稳定回收，别指望玩家自觉。
