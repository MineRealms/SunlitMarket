## 1. 主题定位：当铺二楼开一间行情厅

当铺现有三层生意：柜台收货（顾客求售）、鉴定/赃物（heat/通缉）、执法（检查员）。期货是第四层：**掌柜用自己的库存做对冲盘，给熟客开指数多空**。

- 叙事上完全成立：当铺掌柜本来就低买高卖、囤货赌涨，期货只是把这件事明码标价。
- 玩家动机：农户在收获前锁价（做空 GRAIN 对冲掉价）、矿工囤矿赌涨（做多 ORE）、纯投机客赚波动。
- **柜台与期货共用同一个价格引擎**：柜台收货改变做市库存 → 库存偏斜改变成分 mid → 指数动 → 期货盈亏。这是整个设计的枢纽：现货玩法（收货/倾销）直接变成期货市场的「基本面」，两个系统互相喂数据，而不是两个孤立玩法。

## 2. 现货引擎（E1）的具体决定

### 2.1 定价公式

```
mid = base * clamp( (S0/max(S,1))^e , 0.25, 4.0 )     e = 0.20
ask = mid * (1 + spread/2)   bid = mid * (1 - spread/2)
exec = mid * (1 + k*sign(q)*sqrt(|q|/S0))             k = 0.03
```

- S0 按品类：作物 128、鱼 32、矿 64、魔法材料 16。S 初值 = S0/2。
- **硬约束（启动断言 + 静态检查各加一条）：ask >= shippingValue**。做市商卖价不得低于出货箱，否则无限套利；bid 低于 shipping 是利润来源，保留。
- 每日收盘：S 向 S0 回归 10%（clamp ±4），mid 向 base 回归 5%。跌穿 base*0.4 的物品按底价无限收货（防砸盘归零）。
- 赃物池不参与动态定价，维持固定三价——赃物的问题是执法，不是市场。

### 2.2 存量与开销

每 (merchantId, itemId) 存 stock(int) + mid(int)。600 货池约 4.8 KB 内存，一个 NBT Compound 落盘。计算只在成交时 O(1)。无 tick 常驻成本。

## 3. 指数与 K 线（E2/E3）的具体决定

### 3.1 首发 3 个指数（不是 8 个）

| 指数 | 成分来源 | 成员数(约) | 理由 |
|---|---|---:|---|
| ORE 矿指 | society:blacksmith 货池 | 11 | 玩家关注度最高，GT 前期刚需 |
| GRAIN 谷物指 | society:farmer 货池 | ~60 | 覆盖最广，日常流量最大 |
| FISH 渔指 | society:fisher 货池 | ~40 | 独立波动源，与农业错峰 |

其余 5 个（VEG/ANIMAL/CRAFT/MAGIC/ME）等运行数据证明采样质量后再开。指数少 = 每个指数的成交密度高 = K 线有信息量。

### 3.2 指数公式与权重

```
index = 1000 * exp( Σ w_i * ln(mid_i / base_i) )      // 归一化到 1000 起步
w_i   = 0.7 * (近30日成交额份额, 上限0.10) + 0.3 * (1/成员数)
```

几何平均 + 单品权重上限 10%：任何单品暴涨 4 倍最多抬指数 15%，且抬升必须先经得起「ask>=shipping」约束下的真金白银买入。权重每日收盘重算一次。

### 3.3 采样与存储

- 每 100 tick（5 秒）采样一次 index，更新当前蜡烛 high/low/close；跨日封蜡烛。
- 周期：1D（24000 tick）与 4H（4000 tick）两种；各存 240 根。
- 存储：每指数 480 根 × 5 个 int 约 9.6 KB，8 指数全开也才 77 KB。NBT long[] 打包，随 MarketData 落盘。
- 重启补蜡烛：onServerStarted 检查 lastSampleDay，跨过的日子补 flat 蜡烛（open=close=上根 close），避免断图。

### 3.4 K 线面板

- 只读 Screen：GuiGraphics.fill 自绘，最多 120 根蜡烛 × 2 个矩形（影线 + 实体），无第三方库。**已实现（E3）**。
- 同步：C2S 请求 (index, period) → S2C 返回最近 120 根 × 5 short = 1.2 KB；封盘增量推最后一根。
- 面板顶部标注「掌柜报价指数」——诚实告知这是做市商公式价，不是玩家博弈盘。
- 行情终端方块（挂在当铺里的显示屏）放最后做，第一版 GUI-only，从当铺 GUI 加一个「行情」按钮进入。**已实现：按钮 + `/sunlitmarket chart`，页签切换指数与周期都走服务端重新请求。**

## 4. 期货（E4/E5）的具体决定

### 4.1 合约规格

```
标的       : ORE / GRAIN / FISH 指数
乘数       : 每点 10 spur（可配置 contracts.multiplier）
名义价值   : 指数 1000 点 = 10,000 spur/手，约 2.4 sun
到期       : 开仓后第 7 / 第 30 个游戏日收盘（2.3 / 10 小时现实时间）
结算       : 现金交割，结算价 = 到期前 40 个采样点（200 秒）TWAP
保证金     : 初始 25%（2,500 spur/手），维持 15%
手续费     : 开仓 0.2% + 平仓 0.2% + 交割 0.1%（全部沉没）
仓位上限   : 20 手/人/合约（可配置；FTB 队伍维度用 wantedScope 同款配置项）
准入       : 需要 unlock id sv.mastery（进度门槛，防止开局白嫖杠杆）
```

### 4.2 做市商报价（对手盘）

```
fair  = index * (1 + 0.001 * daysToExpiry)            // 持有成本
quote = fair * (1 +/- 0.005)                          // 0.5% 点差
skew  = fair * (1 - 0.05 * 净敞口/仓位上限总值)        // 净多头越多报价越低
```

对手盘是「掌柜的金库」，余额记在 FuturesData.houseBalance：手续费与点差进账，玩家盈亏从出账。**金库 < -500,000 spur 时禁止开新仓**（提示「账房周转不开」）——这是货币超发的总闸。点差收入在双向流动下长期为正，正常玩不到闸。

### 4.3 逐日盯市 + 强平

- 每日收盘对每个持仓结算一次已实现盈亏（进/出钱包冻结额），重算保证金要求。
- 每 100 tick 检查：equity = 保证金余额 + 未实现盈亏；equity < 维持线 → 市价强平，按 quote 成交并收 2% 惩罚（进金库）。
- equity <= 0 → 保证金归零、仓位关闭。没有穿仓追债——玩家最多亏掉保证金，这是刻意的设计底线。

### 4.4 防操纵四件套（缺一不可）

| 攻击 | 防御 |
|---|---|
| 到期前瞬间砸盘 | 结算价 = 40 采样点 TWAP + 到期前 6000 tick（5 分钟）禁止开新仓 |
| 现货囤积推指数 | 单品权重上限 10% + 指数成分的做市库存有每日均值回归 + ask>=shipping 挡住无成本囤积 |
| 单边挤兑做市商 | 报价偏斜随净敞口线性变差 + 20 手仓位上限 + 金库负余额熔断 |
| 多账号对倒 | 对手盘是做市商不是玩家，对倒只把自己点差磨掉 |

另加 ±20% 日内熔断：单指数单日波动超 20%，该指数期货停盘到次日。

## 5. 与现有系统的接口

| 系统 | 接口 |
|---|---|
| Currency | 新增 freeze/unfreeze API；available = balance - frozen。保证金从 available 冻结，强平/结算后解冻 |
| SavedData | 新增 MarketData（stock/mid/指数/蜡烛）与 FuturesData（持仓/金库/冻结额），都按世界存 |
| OwnerKey | 期货持仓归属用 wantedScope 同款 PERSONAL/TEAM 配置 |
| onServerStarted | ① 补蜡烛 ② 结算跨服到期的合约（用存档里的蜡烛收盘价，确定性结算） |
| onServerTick | 每 100 tick：采样 + 强平检查 + 到期检查；每日收盘：盯市 + 均值回归 + 权重重算 |
| svMastery.js | 期货准入直接复用 sv.mastery 解锁，不新增阶段 |
