# 星际当铺 · 生产力无限性下的经济与阶段锁

> **⚠ §0 / §2 / §4 / §5 已被 `ECONOMY_MODEL_V2.md` 取代**（那份修正了货币创造的错误假设，并给出可断言的 I1–I7）。
> 本文件的 §3 衰减、§6 货单类型、§7 接受仓、§8 期货、§11 JSON 仍然有效。
>
> 前置：`ECONOMY_AND_FUTURES.md` 是框架分析，`FUTURES_ECONOMY_PLAN.md` 是 E1–E4 的实施设计。
> 本文只解决一个问题：**MC 的生产力是无限的，而钱必须是有限的。**
> 目标不是「让交易更有趣」，而是「让交易不可能变成无限刷钱」，同时保留后期玩家倾倒产能的出口。

---

## 0. 一句话结论

> 钱只能由**当铺的现金**创造，当铺的现金只能由**玩家消费**补充。
> 所有回收通道（物品 / 流体 / 能源 / 源质 / 魔力）都换算成同一个「每日可回收金额」预算，
> 而不是「每日可回收数量」。数量可以无限，金额不能。

只要守住这一条，玩家的产能再离谱，也只能把**自己的**每日额度填满，不会通胀。

---

## 1. 问题的本质

| 资源 | 是否可无限量产 | 说明 |
|---|---|---|
| 物品（绝大多数） | 是 | 有产线就有无限产出，边际成本≈电费 |
| 流体 | 是 | 同上，GT 的油/化工线尤其夸张 |
| EU / FE | **极端是** | 等离子/裂变之后，电是「已经解决了的问题」 |
| TC 源质 | 是 | 只要有要素罐和充能，源质可以无限蒸馏 |
| Botania 魔力 | 是 | 花田+火花，挂机就涨 |
| 玩家时间 | 否 | 唯一真正稀缺的东西 |
| 世界生成资源 | 准无限 | 矿脉密度限制的是「速率」，不是「总量」 |
| Boss/结构掉落（原始珍珠等） | 否 | 受重生/结构数量限制，是真正的稀缺品 |

**推论**：任何「X → 钱」的接口，如果 X 的产出速率没有上限，那么「钱/小时」就没有上限。
因此要么给 X 的产出加速率上限（做不到，会毁掉 GT），要么给「X → 钱」加**金额上限**。

## 2. 三条硬约束（建议做成启动断言）

写成静态检查，违反就打日志（或直接拒绝加载对应货单）：

```
C1  sell(item) <= salvage(item)
    「回收价不得超过把它拆成原材料的价值」
    salvage = GT 回收配方（研磨/熔炼/离心）得到的材料按 sell 价求和 × 0.6

C2  buy(item) >= max over recipes(item -> *) of ( Σ buy(inputs) )
    「不得买了拆开卖原料赚钱」

C3  ∀ 玩家 p, ∀ 日 d:  Σ 所有回收通道金额(p, d) <= budget(p, d)
    「每日回收总额封顶」（见 §4）
```

C1 是用户说的「回收只能拆价值很低的内容」的**形式化**：不是人工定低价，而是让 GT 的回收配方自动算出残值。
一台 1000 spur 的机器，拆出来 8 个钢锭，残值 30 spur —— 卖价就只能是 30，不是 1000。

C2 需要一张**配方图**做全图检查（GT 有上万条配方，人工不可能对）。建议：
- 加载期构建 `item -> (recipes producing) / (recipes consuming)`
- 对每个在售物品跑一次最短路（价值传播），输出违规清单到日志
- 违规项自动从「可回收白名单」里剔除，而不是让平衡组去改配方

> 这是整个方案里**唯一必须写代码**的平衡工具。没有它，任何手工定价都会在 600 个货池里漏掉几个套利环。

## 3. 卖价模型：残值锚定 + 数量衰减 + 阶段折价

```
bid(p, i, n) = base_bid(i)
             × tier(playerTier(p), itemTier(i))     // 阶段折价，见 §5
             × decay(n / quota(p, i))              // 数量衰减，见 §3.2
             × stockPressure(S(i))                 // 当铺自己的库存压力
```

### 3.1 残值锚定（C1）
`base_bid(i) = min( 0.6 × salvage(i), 0.5 × craftCost(i) )`
对**不可合成**的物品（Boss 掉落、结构战利品），`salvage` 未定义，走「稀缺品」分支：允许高价回收，但每日额度极小（见 §4.3）。

### 3.2 数量衰减
`decay(x) = max(0, 1 - x)^1.5`，`x = 今日已卖数量 / quota`
- 曲线在 0 附近接近线性（正常玩家感觉不到），在 80% 之后急速下坠（批量倾销直接归零）
- 到 quota 之后**硬性拒收**，不是给 1 spur，是直接不收货。UI 要明确显示「今日已收满」
- quota 按 (玩家, 物品) 记，且全局 quota = Σ玩家 quota × 0.6（防止 20 人一起倾销把当铺打爆）

### 3.3 库存压力
沿用 E1 的 `mid = base × (S0/max(S,1))^e`，但 **e 从 0.20 提高到 0.45**（只对卖价生效，买价仍用 0.20）。
理由：0.20 太平了 —— 供给 10 倍价格只掉到 63%，等于鼓励无限生产。0.45 下 10 倍供给掉到 36%，配合 quota 足够。

## 4. 回收通道：统一成「每日金额预算」

这是本文最重要的机制。**当铺有一本现金账，回收就是它在花钱。**

```
cash(d+1) = cash(d) + sales(d) + refill(d) - buyback(d)
buyback(d) <= cash(d)                  // 硬约束：没钱就不收
refill(d) = min(0.02 × cash(d), cap)   // 外部客商带来的缓慢补充
```

性质：
- 若 `refill = 0`，货币总量**严格守恒**。玩家之间是零和的：你想卖，就得先有人买。
- 这天然形成玩法循环：**想让当铺收你的货，就得先把当铺的货买走**。
- 多玩家时是竞争关系（抢当铺的现金），这正是多人经济该有的张力。
- 不需要任何「反通胀补丁」，因为通胀在数学上不可能发生。

`refill` 存在是为了让新玩家/新赛季能从零起步，取 2%/日 + 上限，缓慢且可控。

### 4.1 各通道的换算（关键：电最不值钱）

| 通道 | 计价 | 每日金额上限 | 备注 |
|---|---|---|---|
| 物品 | `min(0.6×salvage, 0.5×craft)` | 共享预算 | 主体通道 |
| 流体 | 每 mB 单价（按流体稀缺度表） | 共享预算 | 汽油/柴油这类必须有强衰减 |
| EU / FE | **0.02 spur / 1000 EU**（约等于白送） | 单独小额度 | 见 §4.2 |
| TC 源质 | 按要素稀有度，每点 0.5–3 spur | 共享预算 | 源质产量大，必须有 quota |
| Botania 魔力 | 每 1000 mana 0.5 spur | 共享预算 | 同上 |

**为什么电必须几乎不给钱**：GT 的后期电力是「已经解决了的问题」，任何有意义的电价都会变成印钞机。
电的价值应该体现在**别的维度**：把电送进接受仓可以累积「供电信誉」，用来解锁**只能买不能卖**的货单（见 §6），而不是换钱。

### 4.2 能源通道的特殊处理
- 金额上限单独设，且极小（建议 = 中期玩家 3 分钟收入）
- **不接受自动化输入**：接受仓只能玩家右键放入（或每次交互金额上限 = 单次上限）
- 理由：EU 可以被线缆/激光自动灌入，一旦允许自动化，玩家挂机就能吃满额度，等于送钱

### 4.3 稀缺品（原始珍珠这类）
- 只能**买**，回收价 0（或者极低）
- 供给由当铺库存控制，库存由「玩家交付 Boss 掉落」补充
- 这样原始珍珠的价格由真实稀缺性决定，而不是被某个刷怪塔打穿

## 5. 阶段锁：为什么「升压之后能量产上一级」会崩盘

用户指出的现象是对的，而且比想象的更严重：

```
玩家在 LV 阶段：1 小时产 100 个钢 → 卖 100 × 30 = 3000 spur   （正常）
玩家在 LuV 阶段：1 小时产 100000 个钢 → 卖 100000 × 30 = 3,000,000 spur（崩盘）
```

钢的**使用价值**在 LuV 阶段几乎为零，但它的**回收价值**如果还是 30，就是纯印钞。
所以卖价必须随「玩家阶段 − 物品阶段」衰减：

```
tier(playerT, itemT):
    d = playerT - itemT
    d <= 0  -> 1.00      // 同级或更高级：正常价
    d == 1  -> 0.35      // 低一级：还能卖，但明显不划算
    d == 2  -> 0.10      // 低两级：只值运费
    d >= 3  -> 0.00      // 直接拒收（UI 灰掉并说明原因）
```

叙事上完全成立：**当铺的顾客也升级了，没人要你三年前的钢了。**

实现上只需要两个字段：物品的 `tier`（GT 电压等级 / TC 研究阶段 / 模组自定义），玩家的 `tier`（由进度检测得出，见 §5.1）。
两者都是「单调不减」的标量，比较即可。

### 5.1 玩家阶段怎么测（不要问玩家，要测）
按优先级取**已达成过的最高值**，而不是当前持有：
- GT：解锁过的最高电压机器方块（扫描玩家曾放置/合成过的机器，或用 GT 的 `VoltageTier` 进度）
- TC：完成的研究数量 / 是否解锁过某研究
- 通用兜底：玩家背包+末影箱里出现过的最高 tier 物品（单调快照，存在玩家 NBT 里）

**关键：阶段只升不降。** 玩家把机器拆了不会掉阶段，否则可以靠拆机器反复解锁低阶高价。

### 5.2 阶段锁的双向性
阶段锁不只是限制卖，也要限制**买**：
- 高阶物品对低阶玩家**不可见**（否则新手看到 LuV 电路板的价格只会困惑）
- 低阶物品对高阶玩家**保留可买**（补货用），但价格按阶段上调（他反正不在乎钱）

## 6. 只能买 / 定向回收（用户的核心诉求）

三类货单，在数据层就是一个字段 `accept`：

| 类型 | 能买 | 能卖 | 用途 |
|---|---|---|---|
| `TRADE`（普通） | 是 | 是 | 日常补给、农产品、矿物 |
| `BUY_ONLY`（只卖不给收） | 是 | **否** | 格雷前期难做的关键件、原始珍珠、跳阶段加速道具 |
| `SELL_ONLY`（定向回收） | 否 | 是（有限额） | 后期产能出口：汽油、源质、魔力、多余成品 |

`BUY_ONLY` 是这个经济体的**货币出口**：玩家赚的钱必须能买到「用时间换不到的东西」，否则钱没有意义。
候选清单（按「做起来烦，但不该卡死进度」筛选）：
- 格雷前期：钢、聚乙烯、钛、电路板（省掉 2 小时）
- 跨模组瓶颈件：某模组的核心机器、催化剂
- 稀缺品：原始珍珠、Boss 掉落

`SELL_ONLY` 是**产能出口**：让后期玩家把一仓库汽油换成钱，但通过 §4 的预算和 §5 的阶段折价，换不了多少。

## 7. 接受仓（多形态回收的物理载体）

一个方块，四个槽位对应四种「形态」，全部走同一本现金账：

```
[物品槽]  [流体槽]  [能源口]  [源质/魔力口]
```

设计要点：
1. **不做管道输入**。只接受玩家右键放入 / 手持流体容器右键。自动化 = 挂机刷钱。
2. 每次交互后**立刻**给出「本次回收 X，今日剩余额度 Y」，让玩家看见天花板，而不是默默被拒。
3. 能源口给的是**信誉**不是钱（§4.2），UI 要写清楚，否则玩家以为坏了。
4. 回收是**原子**的：物品销毁和记账在同一个 tick 内完成，失败则物品留在槽里。这是防刷物品 bug 的最后一道闸。

## 8. 期货：后期玩家真正的赚钱方式

现货被 §4/§5 封死之后，后期玩家的收入来源应该是**判断力**而不是**产能**：
- 期货用全额保证金（先不做杠杆），盈亏来自指数波动
- 指数由真实成交驱动，几何平均 + 单品权重上限 10%，操纵成本 > 收益
- **结算用 TWAP**（最近 N 个采样均值），不用瞬时价，否则一根大单就能打穿结算价
- 保证金从钱包扣，亏损直接销毁（这是第二个货币出口）

这样「一万成品汽油换钱」是一次性的、有上限的；而「我看对了行情」是可以反复赚的、且不需要产能。

## 9. 平衡目标（可测量的验收标准）

用 `sv_price_audit.py` 的方式实测，而不是拍脑袋：

```
T1  中期玩家（HV）诚实交易 30 分钟收入 ≈ X
T2  后期玩家（LuV）满产线倾销 30 分钟收入 <= 1.5X
T3  任一玩家单日回收总额 <= 当日当铺现金
T4  任意物品：sell <= salvage（C1 零违规）
T5  任意配方环：不存在「买 A → 拆 → 卖 B」正收益（C2 零违规）
T6  货币总量日增长率 <= 2%（refill 上限）
```

T2 是这套设计的成败判据。如果做不到，说明 tier 折价不够狠或 quota 太大。

## 10. 我可能还没考虑到的（需要你拍板）

1. **多账号刷额度**：每日额度按 UUID 记，小号可以翻倍。建议按「账号在线时长加权」或干脆按队伍（team）记账。你要单人体验还是防刷？
2. **离线产线**：区块不加载时 GT 机器不跑，这本身是时间税；但如果装了区块加载器，产能就变成 24 小时。要不要给「离线产出」单独设更低的回收系数？
3. **复制 bug 放大**：任何「物品→钱」接口都是 dup 的放大器。接受仓要不要加「物品必须来自本玩家背包」的校验（成本较高）？
4. **跨模组价值锚**：TC 源质 / Botania 魔力 / FE 的「每 tick 稳定产出」差别很大，换算表需要实测，不能拍脑袋。建议先只开物品+流体，源质/魔力观察一周再开。
5. **赛季与轮换**：服务器整体阶段推进后，老货单要不要下架？下架会让囤货玩家亏损（可能引发不满），不下架会让老物品永远有底价（等于保留印钞口）。建议：**下架但给 7 天缓冲期**，并提前在当铺公告。
6. **价格历史膨胀**：见 §11。

## 11. K 线历史持久化（JSON）

现状：`MarketData` 是 SavedData，每 (指数, 周期) 存 240 根 ring，NBT 里。够用，但不利于外部分析。

建议增加一个**只写不读**的日终导出：
```
config/sunlitmarket/history/<indexId>_<period>.json
{ "index": "sv.produce", "period": 24000, "candles": [[bucket,o,h,l,c], ...] }
```
- 每游戏日收盘写一次，写临时文件再 `Files.move(ATOMIC_MOVE)`（避免半截文件）
- 保留最近 2000 根，超出裁剪头部
- 服务端读 NBT 为准，JSON 只是镜像 —— 删了不会坏档
- 好处：可以直接喂给 pandas 做平衡分析，不用解析 NBT

## 12. 建议的实施顺序

| 阶段 | 内容 | 理由 |
|---|---|---|
| **S1** | `accept` 字段（TRADE / BUY_ONLY / SELL_ONLY）+ 每日金额预算 + quota 衰减 | 这三样是防崩盘的最小闭环，缺一个都不安全 |
| **S2** | 残值表（GT 回收配方 → salvage）+ C1/C2 静态检查 | 让「回收只能拆低价值」变成自动的，而不是手填 |
| **S3** | 阶段锁（物品 tier + 玩家 tier + 折价曲线） | 解决「升压后量产上一级」 |
| **S4** | 接受仓（先只做物品+流体，右键交互） | 玩家能摸到的产能出口 |
| **S5** | 能源/源质/魔力通道（先只给信誉，不给钱） | 观察一周再决定要不要给钱 |
| **S6** | 期货结算（全额保证金 + TWAP） | 后期玩家的收入来源 |
| **S7** | 日终 JSON 导出 | 为后续平衡提供数据 |

S1 必须先做，因为它是**唯一能让其它功能安全上线的前提**。
